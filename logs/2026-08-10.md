## 막힌 것 2 — 루프 버전의 결함

원리 버전(for 루프)과 벡터화 버전을 둘 다 쓰고 `check_equivalence()`로 대조하게
만들었는데, 처음 작성한 루프가 **청산일에 발생한 신호를 놓쳤다.**

```python
if position_open:
    if elapsed >= holding_days:
        ...청산...
    continue          # <- 청산한 날의 진입 판정을 건너뛴다
```

청산일 종가에 확정된 신호는 다음 날 진입이므로 보유 구간이 겹치지 않는다.
즉 **유효한 거래인데 루프만 빠뜨렸다.** 벡터 버전은 잡았다.

`continue`를 없애 두 구현을 맞췄고, 검증 3번(신호 t=0과 t=4, 첫 청산이 index 4)에
이 케이스를 고정해뒀다. **실데이터에서는 이 상황이 발생하지 않았지만**
(20조합 전부 등가), 발생했다면 조용히 갈렸을 것이다.

## 방법론 기록 — 왜 원리 버전을 남기는가

벡터화 버전이 빠르다는 이유로 루프를 지웠다면, 오늘 발견한 결함은 **발견될 기회가
없었다.** 두 구현이 갈렸기 때문에 잡힌 것이고, 하나만 있었으면 그게 정답이 된다.

중복 진입 금지 때문에 완전한 벡터화는 애초에 불가능하다 — 다음 진입 가능 시점이
직전 청산 시점에 의존하는 **경로 의존** 구조다. 그래서 벡터 버전도 신호 인덱스만
훑는 루프이고, 얻는 것은 6,684일 → 사건 수만큼으로 줄어드는 것뿐이다.
